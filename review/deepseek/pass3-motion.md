- `lib/ui/zed/zed_motion.dart` — `_ZedPressScaleState._to` / `_controller`: `_controller` is a default bounded `AnimationController(vsync: this, value: 1)`. If `pressedScale` is `1.07` (the documented Glass press), `_to(1.07)` runs a spring toward a target above `upperBound` 1.0; the controller value clamps at 1.0, so the 1.07 press scale never appears. Evidence: default bounded controller plus `_controller.animateWith(SpringSimulation(..., target, 0))` and `Transform.scale(scale: _controller.value, ...)`.

- `lib/ui/zed/zed_motion.dart` — `_ZedPageTransitionState.build` / `_transform`: the transform direction for every entry is derived from the current `widget.forward`, not the direction at which that entry started animating. Scenario: LTR slide, navigate forward A→B; while A is still exiting left, navigate back. `widget.forward` flips, so the old A exit entry immediately uses the opposite `sign` and jumps from leftward offset to rightward offset. Evidence: `final sign = (widget.forward ? 1 : -1) * layoutSign;` is applied to all `_entries`, and `_transform` also reads `widget.forward` directly for depth/curtain.

- `lib/ui/zed/zed_motion.dart` — `_ZedPageTransitionState.didUpdateWidget`: when the current top page becomes an exit, its existing controller is disposed and a new exit controller is created from default value 0. If the top page was still mid-entrance, its visual state is discarded and it jumps to the exit’s t=0 state. Scenario: navigate A→B, then before B’s entrance finishes navigate B→C; B jumps from its partially entered position/opacity to fully entered, then starts exiting. Evidence: `top.controller.dispose();` followed by `exit.controller = AnimationController(vsync: this);` and `exit.controller.forward()`, with no transfer of the old progress.

- `lib/ui/zed/zed_motion.dart` — `_ZedPageTransitionState._transform`, `ZedTransition.elastic` entering: the comment says `t` is the spring simulation value and “may overshoot,” but the controller is a default bounded `AnimationController` created in `_add`, so values above 1 are clamped. `dy = size.height / 8 * (1 - t)` and `scale = 0.9 + 0.1 * t` therefore never overshoot past the final state; after the spring crosses 1, the clamped value returns below 1 and the page moves/scales backward. Evidence: bounded `AnimationController(vsync: this)` in `_add` plus the overshoot assumption in the elastic branch.

- `lib/ui/zed/zed_motion.dart` — `_ZedPageTransitionState._transform`, `ZedTransition.flip` entering: the delayed fade is computed incorrectly. At `t = 90 / 360`, the condition switches from `0.0` to `fade(220, 360)`, which equals `0.25 * 360 / 220 ≈ 0.409`; multiplied by `alpha`, opacity jumps to about `0.19` instead of starting at 0 after the delay. Evidence: `t < 90 / 360 ? 0.0 : fade(220, 360)` with `fade` implemented as `(t * totalMs / durMs).clamp(...)`; the 90 ms delay is never subtracted.

- `lib/ui/zed/zed_motion.dart` — `ZedEntrance` static `windowStart`: the window anchor is process-global and is only reset by the test hook `resetWindow()`. If the server-list screen is disposed and rebuilt after 800 ms, every new `ZedEntrance` sees the old static `windowStart`, fails the 800 ms check, and renders unanimated. Evidence: `static DateTime? windowStart;`, `ZedEntrance.windowStart ??= now;`, and the early return when `now.difference(...) > 800ms`; no production reset appears in this file.
