- **app/lib/ui/accounts_page.dart — `_AccountCard.build`**: The new `DefaultTextStyle.merge` wrapper passes `style: null` when `customConfigCardText` is unset. That is not a no-op: `DefaultTextStyle.merge` with neither `style` nor `baseStyle` resolves to an empty `TextStyle`, overriding the ambient default text style for descendants that rely on it (e.g. `_StatusPill` or any unstyled text). Default settings can therefore change card text styling/color. Evidence: `style: cardText == null ? null : TextStyle(color: cardText)` around the card child.

- **app/lib/ui/settings_page.dart — `_SettingsPageState._general` / `pixelLook`, profile `_Choice<String>`**: Selecting the “Custom” profile (`id == ''`) does not clear `p.profileId`. `zedProfileOf('')` returns null, so `applyZedProfile` is skipped and `p.profileId` remains the previous preset. After `save()`/rebuild the dropdown still shows the preset; the user cannot return to custom colors. Evidence: `value: zedProfileOf(p.profileId) != null ? p.profileId : ''` and `onChanged: (id) { final profile = zedProfileOf(id); if (profile != null) applyZedProfile(p, profile); save(); }`.

- **app/lib/ui/settings_page.dart — `_SettingsPageState._general` / `interfacePanel` and `bentoLook`**: With Bento design selected, two `ZedNavStyle` controls with the same label are rendered: one bound to `prefs.navStyle`, one to `prefs.bento.navStyle` (`b.navStyle`). They can diverge, and only one can actually control the rendered navigation style, leaving the other dead/conflicting. Evidence: `_Choice<ZedNavStyle>(title: l.zedNavStyle, value: prefs.navStyle, ...)` in `interfacePanel` and `_Choice<ZedNavStyle>(title: l.zedNavStyle, value: b.navStyle, ...)` in `bentoLook`.

- **app/lib/ui/settings_page.dart — `settingsIndex` + `_SettingsPageState._general` / `interfacePanel`**: `settingsIndex` unconditionally indexes every Zed setting under `SettingsSection.general`, while the actual UI only renders the active design’s sub-panel (`switch (prefs.design)`).
