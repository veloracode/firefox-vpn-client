- **lib/ui/zed/zed_motion.dart — `_ZedPageTransitionState.didUpdateWidget`**: When a still-entering page is converted into an exit, the code constructs the exit with `widget.forward` instead of the entry’s stored `forward`: `final exit = _Entry(top.key, top.child, false, widget.forward);`. Scenario: navigate A→B forward, then back to A before B finishes entering. B’s entry started with `forward=true`, but its new exit gets `forward=false`; transforms that depend on `e.forward` (slide/depth/curtain) run in the wrong direction. This contradicts `_Entry.forward`’s own comment: “An exit must keep its own direction even if the user reverses direction while it is still on screen.”

- **lib/ui/zed/zed_motion.dart — `_ZedPageTransitionState.didUpdateWidget`**: Converting an in-progress entering page to an exit creates a fresh controller at default value `0`: `exit.controller = AnimationController(vsync: this);`, after disposing `top.controller`. If the page was partway through an entrance, especially an elastic/spring entrance, its current transform is not the rest transform. The new exit begins at `t=0`, which is the settled/rest transform, so the page visibly snaps to rest before exiting. Evidence: no value is carried from `top.controller.value` into `exit.controller`.

- **lib/ui/zed/zed_kit.dart — `_GlassTabBarState._shrinkListener`**: At the top boundary, the bar clears `_shrunk` but does not reset `_downAccum`: `if (c.offset <= 0 && _shrunk) setState(() => _shrunk = false);`. Scenario: scroll down enough to shrink (`_downAccum > 48`), scroll up only 5 dp to offset 0, then scroll down 1 dp. The up-branch did not reset because `_upAccum <= 8`; `_downAccum` is still >48, so the next tiny down-scroll immediately shrinks the bar again instead of requiring the intended 48 dp of sustained down-scroll.

- **lib/ui/zed/zed_kit.dart — `_GlassTabBarState.didUpdateWidget` / `_shrinkListener`**: A page change with the same tab index sets `_shrinkAnchorStale = true` but does not reset `_downAccum` or `_upAccum`. The stale branch only does `_lastSeen = c.offset; return;`. Scenario: scroll down 40 dp on page A, navigate to a detail page in the same tab (`widget.index == old.index`), then scroll down 9 dp on the detail page. The first scroll only re-anchors; the next adds to the old 40 dp and shrinks after 9 dp instead of 48 dp on the new page.

- **lib/ui/zed/zed_motion.dart — `_ZedPageTransitionState._transform`, elastic entrance branch**: Elastic entering uses raw spring value as `t`, then computes opacity with `fade(180, 1000)`, where `fade` does `(t * totalMs / durMs).clamp(...)`. This treats the spring value as linear elapsed time. The spring reaches `t ≈ 0.18` early (while still offset/scaled), so the page becomes fully opaque long before the intended 180 ms fade; the code’s own “opacity runs on its own duration inside the controller’s total duration” comment does not hold for the spring-driven branch.
